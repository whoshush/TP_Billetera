ANÁLISIS DE COMPLEJIDAD ASINTÓTICA (ÁLGEBRA DE ÓRDENES)

Método bajo análisis: realizarTransferencia

Código fuente analizado

// Método auxiliar interviniente en la clase Billetera:
private Cuenta encontrarCuentaPorCvu(String cvu) {
for (Usuario u : usuarios.values()) {               // O(U) - Donde U es la cantidad de usuarios
Cuenta c = u.buscarCuenta(cvu);                 // O(1) - Búsqueda en HashMap por clave (CVU)
if (c != null) {                                // O(1)
return c;                                   // O(1)
}
}
return null;                                        // O(1)
}

@Override

Justificación paso a paso (Defensa para la Cátedra)

Para determinar el costo temporal T(n) del método realizarTransferencia, se aplica el álgebra de órdenes sobre sus bloques secuenciales:

A. Análisis del método auxiliar 'encontrarCuentaPorCvu':
El algoritmo debe buscar una cuenta por su CVU de forma global, pero la estructura del sistema agrupa las cuentas dentro de cada objeto Usuario. Por lo tanto, el ciclo for-each debe recorrer la colección de usuarios registrados. Sea 'U' la cantidad total de usuarios en el sistema. Dentro del ciclo, la instrucción 'u.buscarCuenta(cvu)' accede al diccionario interno de cada usuario (un HashMap que indexa sus cuentas por CVU), lo cual tiene un costo constante promedio de O(1).
En el peor escenario (que la cuenta no exista o pertenezca al último usuario del mapa), el bucle se ejecutará 'U' veces.
Complejidad del método auxiliar: O(U) * O(1) = O(U)

B. Análisis de las búsquedas en 'realizarTransferencia':
El flujo principal invoca el método auxiliar dos veces consecutivas (una para la cuenta de origen y otra para la de destino):
T(búsquedas) = O(U) + O(U) = O(2U)
Por las propiedades del álgebra de órdenes, las constantes multiplicativas se descartan en el análisis asintótico, por lo que el costo de las búsquedas se reduce a O(U).

C. Análisis del bloque transaccional (Bloque try):
Todas las instrucciones de validación, actualización de saldos e instanciación de la operación ejecutan operaciones aritméticas y asignaciones directas de costo constante O(1).
Finalmente, el registro del objeto Transferencia se realiza mediante tres operaciones '.put()' en sus respectivos diccionarios basados en tablas de hash (el historial de origen, el de destino y el mapa global del sistema). Al ser estructuras HashMap, la inserción por clave tiene un tiempo de ejecución promedio de O(1).
Complejidad del bloque de transacciones: O(1) + O(1) + ... + O(1) = O(1)

Conclusión y Cálculo Final

El costo temporal total de la operación es la suma de sus partes secuenciales:

T_Total = T(búsquedas) + T(transacción)
T_Total = O(U) + O(1)

Aplicando la regla de la suma en el álgebra de órdenes, el término de mayor orden (el comportamiento lineal) domina sobre el término constante.

Complejidad Final del Método: O(U)
(Donde 'U' representa la cantidad total de usuarios registrados en la plataforma).
