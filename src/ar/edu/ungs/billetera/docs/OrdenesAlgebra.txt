ANÁLISIS DE COMPLEJIDAD ASINTÓTICA (ÁLGEBRA DE ÓRDENES)

================================================================================
Método bajo análisis: realizarTransferencia (flujo completo con delegación)
================================================================================

Código fuente analizado:

// Búsqueda lineal de cuenta (sin mapa global en Billetera):
public static Cuenta buscarCuentaEnSistema(Collection<Usuario> usuarios, String cvu) {
    for (Usuario usuario : usuarios) {              // O(U)
        Cuenta cuenta = usuario.buscarCuenta(cvu);    // O(1) - HashMap por CVU
        if (cuenta != null) return cuenta;
    }
    return null;
}

// Método principal en Billetera (fachada):
public void realizarTransferencia(String cvuOrigen, String cvuDestino, double monto) {
    // validaciones O(1) ...
    Cuenta origen = buscarCuenta(cvuOrigen);          // O(U × C)
    Cuenta destino = buscarCuenta(cvuDestino);        // O(U × C)
    origen.realizarTransferencia(destino, monto, id, fecha, registro);
}

// Lógica delegada en Cuenta:
public void realizarTransferencia(Cuenta destino, double monto, String id, String fecha, RegistroOperaciones registro) {
    try {
        validarOperacion(monto);                      // O(1) - polimorfismo
        destino.validarDeposito(monto);               // O(1) - polimorfismo
        extraer(monto);                               // O(1)
        destino.depositar(monto);                     // O(1)
        // crear Transferencia aprobada O(1)
    } catch (...) {
        // registrar rechazada en origen, destino y registro global: 3 × O(1)
    }
    // registrar aprobada: 3 × O(1)
}

================================================================================
Análisis por subtipo: validarOperacion y validarDeposito
================================================================================

CuentaRegular.validarOperacion(monto):
    - Comparación monto <= 0                          O(1)
    - Comparación saldo < monto                         O(1)
    Total: O(1)

CuentaRegular.validarDeposito(monto):
    - Comparación monto <= 0                            O(1)
    - Comparación saldo + monto > 5_000_000             O(1)
    Total: O(1)

CuentaPremium.validarOperacion(monto):
    - Comparación monto <= 0                            O(1)
    - Comparación saldo < monto                         O(1)
    Total: O(1)

CuentaPremium.validarDeposito(monto):
    - Comparación monto <= 0                            O(1)
    Total: O(1)

CuentaCorporativa.validarOperacion(monto):
    - Comparación monto <= 0                            O(1)
    - Comparación saldo < monto                         O(1)
    Total: O(1)

CuentaCorporativa.validarDeposito(monto):
    - Comparación monto <= 0                            O(1)
    Total: O(1)

Cuenta.extraer(monto):
    - Resta aritmética y asignación                     O(1)

Cuenta.depositar(monto):
    - Suma aritmética y asignación                      O(1)

================================================================================
Método bajo análisis: obtenerTotalInvertido
================================================================================

public double obtenerTotalInvertido(String dniUsuario) {
    return obtenerUsuario(dniUsuario).obtenerTotalInvertido();  // O(1)
}

El acumulador totalInvertido en Usuario se actualiza al invertir (sumar),
precancelar (restar) y vencer (restar). La consulta es acceso directo a un
campo numérico.

Complejidad: O(1)

================================================================================
Justificación paso a paso (Defensa para la Cátedra) — realizarTransferencia
================================================================================

A. Búsqueda de cuentas (buscarCuentaEnSistema):
    Se recorre la colección de usuarios (U usuarios) y, en el peor caso, se
    consulta el HashMap de cuentas de cada uno (C cuentas por usuario en promedio).
    T(búsqueda) = O(U × C) por cada invocación.
    Se invoca dos veces (origen y destino): O(2 × U × C) = O(U × C).

B. Bloque transaccional (Cuenta.realizarTransferencia):
    Todas las validaciones polimórficas, extracción, depósito e instanciación
    ejecutan operaciones de costo constante O(1).
    El registro en HashMap (cuenta origen, cuenta destino, registro global)
    es O(1) por inserción.
    T(transacción) = O(1)

C. Generación de ID y fecha:
    contadorTransferencias++ y Utilitarios.hoy(): O(1)

================================================================================
Conclusión — realizarTransferencia
================================================================================

T_Total = T(búsqueda origen) + T(búsqueda destino) + T(transacción)
T_Total = O(U × C) + O(U × C) + O(1)
T_Total = O(U × C)

La operación de transferencia en sí (validar → crear → ejecutar) es O(1) una
vez encontradas las cuentas. El costo total incluye la búsqueda lineal al haber
eliminado el mapa global cuentasPorCvu de Billetera, delegando la resolución
de CVU a recorrido sobre usuarios.

Nota: Si U y C se consideran acotados por el dominio del problema (cantidad
moderada de usuarios y cuentas), el comportamiento práctico sigue siendo
eficiente para el TP.
